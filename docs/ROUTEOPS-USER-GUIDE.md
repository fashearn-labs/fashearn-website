## Documentation principles

- Write for a first-time, non-technical delivery operator.
- Use the real RouteOps interface rather than mock screens.
- Keep one screen/task per page wherever practical.
- Keep screenshots clean: exclude browser chrome, Windows taskbar and desktop wallpaper.
- Keep text short and task-based.
- Distinguish the normal daily workflow from advanced/occasional tools.
- Screens shown from the public demo must use fictional data only.
- Clearly state that real customer or personal data must not be uploaded to the public website demo.

## Normal workflow

Dashboard -> Drivers (when required) -> Daily Operations -> Issues & Review -> Reports & Analysis

## Advanced / occasional workflow

- Smart Import / Customer Onboarding: initial or additional business data
- File Mapping / Controlled Import: carrier file mapping and validation
- Recalculation: safe preview of rate/pay-rule changes
- Scenario Analysis / Contract Comparison: commercial modelling and decision support

## Update rule

When the RouteOps UI or behaviour changes, update only the affected guide pages and regenerate the complete PDF pack so page ordering and section PDFs stay consistent.
